# 章节评论侧边栏技术方案

## 1. 结论

推荐采用“CSV 预处理 + 当前原生前端渲染”的实现路线。

现有页面是单文件原生 HTML/CSS/JS，已经具备章节正文、段评气泡、评论抽屉、段落定位、回复展开等基础结构。本期核心工作不是重建页面，而是把演示评论数据替换为真实评论索引，并补齐“按评论对象聚合、按标签筛选、按段落/标题筛选”的状态逻辑。

不建议此阶段引入 React、Vue、Tailwind、打包工具或运行时 CSV 解析库。它们会放大改造面，也不符合当前项目保持单文件页面和轻量协作的约定。

## 2. 技术路线

### 2.1 数据预处理

新增一个开发期脚本，将原始 CSV 转成前端可直接消费的结构化数据。脚本建议使用 Python 标准库 `csv/json`，不引入新依赖。

预处理脚本负责：

1. 读取 CSV。
2. 区分一级评论和二级回复。
3. 按 `段落ID` 建立评论对象。
4. 按 `顶级评论id` 将回复挂到对应一级评论。
5. 拆分 `作者视角_固定标签` 与 `作者视角_内容标签`。
6. 生成评论数量、标签数量、段落索引等前端索引。
7. 过滤空正文、孤儿回复等异常数据，并输出简要统计。

运行态页面不直接解析 CSV，避免把 56 列原始数据、转义 JSON、审核字段和 IP 等无关信息带到浏览器里。

### 2.2 运行态数据文件

有两种可选落地方式：

1. **推荐 MVP：生成 JS 数据块并内联到 `index.html`**
   保持当前单文件页面约定，生成 `var COMMENT_DATA = {...}` 形式的数据块，替换现有 `SECTION_POOL / COMMENT_TAGS / SECTION_COUNTS` 的演示数据。

2. **后续可选：独立 `data/comments.generated.json` 或 `comments.generated.js`**
   适合评论数据继续膨胀、多章节复用、或接入真实接口前的过渡。但这会改变“单文件即可运行”的当前约定，需要团队确认。

当前更建议先采用第 1 种，让页面仍然只依赖 `index.html`。

## 4. 排序策略

当前 CSV 中一级评论的 `自定义排序` 全为 `-1`。结合最新 PRD 口径，建议默认排序为：

1. 有有效 `sortValue` 时，`sortValue` 越小越靠前。
2. `sortValue` 为空或 `-1` 时，按 `likeCount` 降序。
3. 点赞数相同则按原始 CSV 行号稳定排序。

这样“每段展示前 3 条”更接近作者优先看重点反馈的使用场景，也避免刷新后顺序跳动。

### 4.1 四档排序的分工（PRD §10.4）

`sortComments(list)` 只负责**单条一级评论**在列表内的排序（默认/最热/最新/长评四个 comparator），聚合块之间的顺序由 `renderAllComments` 控制：

| 排序 | 聚合块顺序（全部评论视图） | 块内/单对象一级评论 |
|------|--------------------------|---------------------|
| default | 章评 → 段落序 → 未匹配 | sortValue 升序兜底点赞降序 |
| hot | 按 `target.totalCount`（含回复）降序；未匹配仍最后 | 点赞数降序 |
| latest | **不聚合**：拍平所有命中的一级评论按 `createdAt` 倒序 | createdAt 倒序 |
| long | **不聚合**：拍平所有命中的一级评论按正文长度倒序（忽略空白） | `body` 去空白后字符数降序 |

「最新」「长评」是对聚合模式的降级渲染：复用 `renderParagraphCommentItem` 单条卡片模板，去掉 `.cm-full-module` 外壳与 `.cm-section-link` 展开按钮；一级评论的二级回复展开行为保持不变。

切换排序 tab 后评论列表 `scrollTop = 0`（与标签筛选一致）。

### 4.2 「最新」「长评」模式的性能权衡

拍平渲染 4,465 条一级评论时 DOM 数量显著增大（每条约 15 个节点）。MVP 直接一次性渲染（实测秒级可完成），不引入虚拟列表；若后续评论量级达到数万条再考虑分页或虚拟滚动。

### 4.3 「长评」排序的口径

字数取 `body.replace(/\s/g,'').length`（中文正文忽略空白与换行；标点计入）。该口径同步用于冒烟测试断言，避免后端字段重命名后回归。

## 5. 前端改造点

### 5.1 替换演示数据

当前页面中这些数据需要替换或改造：

- `SECTION_COUNTS`：改为从 `COMMENT_DATA.targets[].totalCount` 得到。
- `SECTION_POOL`：移除演示池，改为真实一级评论和回复。
- `COMMENT_TAGS`：改为从 `COMMENT_DATA.tagCounts` 渲染。

### 5.2 统一状态模型

建议保留当前原生 JS 状态变量，但收敛为下面几个状态：

```js
var commentState = {
  view: 'all',              // all | target
  selectedTargetId: null,   // -1 表示章评，0+ 表示段评
  activeTag: '全部',
  sort: 'default',
  hoverTargetId: null
};
```

所有渲染函数都从这个状态读取数据，避免标签、段落、排序之间互相覆盖。

### 5.3 全部评论视图

全部评论视图按目标对象聚合：

1. 遍历正文段落顺序。
2. 过滤当前标签命中的一级评论。
3. 每个有评论的段落展示前 3 条。
4. 超过 3 条显示“查看本段 n 条评论”。
5. 最后追加章评聚合块。

二级回复不参与标签命中判断，只随父级评论展示。

### 5.4 单对象评论视图

进入单对象视图后：

1. `selectedTargetId` 记录当前段落或标题。
2. 侧边栏展示该对象下所有一级评论。
3. 默认不展示顶部标签筛选。
4. 保留“返回全部评论”入口。
5. 中间正文对应段落或标题保持高亮。

### 5.5 正文气泡

气泡计数从真实评论聚合结果读取：

1. `targetId = -1` 的计数显示在标题后。
2. `targetId >= 0` 的计数显示在对应段落后。
3. `0` 不显示。
4. 大于 `999` 显示 `999+`，`title` 属性保留真实数量。

定位正文时优先使用 `段落ID`，不要用 `评论对象` 文本反查。CSV 中评论对象文本存在空值、空格和换行差异，只适合展示和数据校验。

### 5.5.2 热度三档配色（PRD §8.4）

正文气泡与侧栏引用行计数气泡统一为三档红系渐进：

| 档位 | 阈值 | class | 颜色 |
|---|---|---|---|
| 热点 | ≥ 100 | `lv-red` | `#FF3B4F`（品牌红） |
| 活跃 | 30 – 99 | `lv-amber` | `#C87A16`（琥珀） |
| 低热 | < 30 | `lv-mute` | `#6F737A`（灰） |

实现要点：

1. `heatClass(n)` 收敛为三档（`≥100 lv-red / ≥30 lv-amber / 其余 lv-mute`），不再产出 `lv-orange-red`、`lv-orange`；CSS 选择器同步收敛。
2. `.para-bubble` / `.chap-bubble` 各档只改 `color`（描边 `border:1px solid currentColor` 自动跟随），背景保持半透明白，避免大改视觉。
3. `.cm-ref-bubble` 渲染处（`renderFullReference` / `renderUnmatchedModule`）拼接 `heatClass(totalCount)`；CSS 新增 `.cm-ref-bubble.lv-amber`、`.cm-ref-bubble.lv-red` 的 `color` + `border-color`，`lv-mute` 沿用基础灰样式；hover 品牌红填充不变。
4. 冒烟测试断言：三档 class 落点、颜色值、以及同一 `targetId` 在正文气泡与侧栏 ref-bubble 的档位一致。

### 5.6 评论正文清洗 [fn=N]（PRD §9.1）

起点评论文本携带脚注标记 `[fn=N]`（样例 916 条）。清洗放在渲染层 `commentBodyHtml`：

```js
var body = escapeHtml(c.body || '');
body = body.replace(/\[fn=\d+\]/g, '');
```

- 先 escape 再正则清洗：escapeHtml 不转义 `[` `]` `=`，正则不受影响。
- CSV 与内联 `COMMENT_DATA` 保留原始文本；若日后改为上标展示，只动这一处。
- 回复正文复用同一函数，自动生效。

### 5.7 标签云折叠态选中可见（PRD §11.2.1）

列表滚动折叠标签云后，选中标签可能落在可视区之外。实现 `syncSelectedTagInView()`：折叠态下对 `.cm-tag.on` 执行 `scrollIntoView({block:'nearest'})`；触发点为标签点击切换与列表滚动引起的折叠态变化。

### 5.8 Hover 原文防误触：指针轨迹判定（PRD §13.1.1）

采用行业通行的 hover intent 方案（计时窗 + 位移阈值）：

1. `mouseenter` 记录起点坐标，启动 150ms 观察窗定时器。
2. 观察窗内 `mousemove` 累计位移（|dx|+|dy|）超过 20px 时判定为「扫过」，取消定时器、不触发滚动。
3. 观察窗自然到期且未取消时才调用 `scrollToTarget`。
4. `mouseleave` 时清除定时器与临时高亮。

模块级 `hoverIntent` 状态保存当前观察窗信息，避免多个评论对象之间残留未决定时器。

### 5.9 灵感便签（PRD §17）

#### 5.9.1 自定义 tooltip 组件

原生 `title` 属性无法满足「点击后立即切换 tooltip 文案并保持显示」，因此实现全局单例 tooltip：

- DOM：`<div id="cmTooltip">` 挂在 body 末尾，`position:fixed`、黑底白字圆角、`pointer-events:none`。
- `showTooltip(anchor, text)`：读取锚点 `getBoundingClientRect()`，定位在锚点上方居中（顶部对齐 anchor.top - tooltip 高 - 8px）。
- `hideTooltip()`：隐藏（display:none）。
- 事件流：
  - plus 按钮 `mouseenter` → 300ms 后显示「存为灵感便签」；`mouseleave` → 隐藏。
  - plus 按钮 `click` → 立即显示「已保存」，设 1.5s 自动消失定时器；显示期间 `mouseleave` 不触发隐藏（点击态优先于 hover 态）。

#### 5.9.2 便签 DOM 与 CSS（Figma 98-14975）

```html
<div class="cm-note" style="left:..px;top:..px;z-index:..">
  <div class="cm-note-head">
    <button class="cm-note-close">close SVG 28×28</button>   <!-- 右上角关闭；标题栏其余区域为拖动手柄 -->
  </div>
  <div class="cm-note-body" contenteditable="true" spellcheck="false">{正文}<br><br>——用户…的评论</div>
</div>
```

MVP 演示版标题栏只有一个关闭按钮在右上角，不渲染 drag 手柄 / plus-circle / content-fold。

CSS 关键规格：`position:fixed`、263×227、`background:#FFF6BA`、`border:1px solid rgba(20,30,41,.12)`、`box-shadow:0 6px 22px rgba(0,0,0,.24)`、`border-radius:8px`；标题栏高 36px（padding 4px 8px，`justify-content:flex-end` 让关闭按钮贴右）；内容区 `overflow-y:auto`、文字 14px/25px rgba(20,30,41,.92)、`contenteditable` 可编辑（focus 时仅显示文字光标，不加 outline）。

内容渲染顺序为 `{bodyHtml}<br><br>——用户{guid}在《没钱修什么仙》第1章 面试的评论`，正文在前 + 空行 + 破折号署名。

#### 5.9.3 位置 / 层级 / 偏移叠放

- 模块级状态：`noteZ`（当前最高 z-index，初始 99999）、`noteCount`（创建序号）、`savedNoteKeys`（commentId → true 防重复）。
- 新便签位置：`left = 16 * (noteCount % 10)`、`top = 16 * (noteCount % 10)`（左上角 + 步进偏移，mod 10 防溢出屏幕）。
- 点击便签任意区域 → `zIndex = ++noteZ`（提升到最顶层）。

#### 5.9.4 拖动与编辑

- 标题栏（排除关闭按钮）`pointerdown` → 记录起始坐标与便签当前位置，`setPointerCapture`。
- `pointermove` → 更新 `left/top`（限制便签不完全拖出视口：left ∈ [-width+40, innerWidth-40]，top ≥ 0）。
- `pointerup` → 释放捕获。拖动位移 > 4px 时标记「已拖动」，抑制 click 冒泡避免误触关闭按钮。
- MVP 演示版标题栏只有一个关闭按钮（贴右上角 `justify-content:flex-end`），不渲染拖动手柄；**拖动触发点是标题栏**（内容区留给编辑）。
- 内容区 `contenteditable`：点击正文直接定位光标编辑（原生行为）；拖动只从标题栏发起，两者互不干扰。便签本体 `pointerdown` 仍负责置顶（zIndex 递增），不 preventDefault（保证编辑光标可用）。

#### 5.9.5 事件绑定策略

4465 条评论 × 每条 1 个 plus 按钮，逐个 `addEventListener` 内存开销大。采用**事件委托**：在 `#cmDrawer`（或 document）上监听 click/mouseover/mouseout，通过 `e.target.closest('.cm-meta-note')` 命中 plus 按钮后处理。渲染函数只输出 data 属性（`data-cid` 存评论 id），不在渲染期绑定。

### 5.10 Hover 菜单（PRD §18）

通用 popover 组件 + 三处触发：

```html
<span class="cm-menu-wrap">                   <!-- toolbar 上的 trigger：包住按钮与 popover，无缝 -->
  <button class="cm-filter" id="cmFilterBtn">…</button>
  <div class="cm-popover cm-popover-right">  <!-- 锚定到 trigger 右下角 -->
    <button class="cm-menu-item" data-action="filter-primary">仅一级评论</button>
    …
  </div>
</span>

<span class="cm-av-wrap">                     <!-- 头像 trigger：包住 .av 与 popover -->
  <span class="av">…</span>
  <div class="cm-popover cm-popover-avatar">  <!-- 锚定到 .av 左下方 -->
    <button class="cm-menu-item" data-action="user-all">此读者所有评论</button>
    …
  </div>
</span>
```

CSS 关键规格：

- `.cm-menu-wrap`：包住 toolbar 按钮与 popover，`position:relative; display:inline-flex; align-items:center`。
- `.cm-popover`：`position:absolute; top:100%; right:0; margin-top:4px; min-width:140px; background:#fff; border:.5px solid var(--color-border-tertiary); border-radius:8px; box-shadow:0 4px 16px rgba(0,0,0,.08); padding:4px 0; opacity:0; visibility:hidden; pointer-events:none; transition:opacity .12s ease; z-index:9999`。

**toolbar 菜单的 hover gap 修复（commit dad548d）**：

- popover 与 wrap 之间有 4px 间隙（margin-top），鼠标穿越间隙时 wrap 的 `:hover` 状态掉线，popover 立刻隐藏 + pointer-events:none，菜单项无法点击。
- 改用 JS hover：`setupMenuWrapHover(wrap)` 给 wrap + popover 各绑 mouseenter/mouseleave，mouseenter 加 `.open`、mouseleave 150ms 后移除，给鼠标穿越间隙留出窗口。
- CSS 保留 `.cm-menu-wrap:hover .cm-popover{opacity:1;visibility:visible;}` 作为视觉渐变兜底，`.cm-menu-wrap.open` 接管 pointer-events。

**头像 popover**（独立处理，避免 4465×DOM 膨胀）：

- 全局单例 `#cmAvPopover`，`position:fixed` 浮动定位。
- 事件委托：`document.addEventListener('mouseover')` 命中 `.av` 后按 `getBoundingClientRect` 定位 + 动态填充菜单项；mouseout 离开头像或 popover 都走 180ms 隐藏。

事件委托：菜单项点击统一在 `#cmDrawer` 上 `addEventListener('click', ...)`，命中 `.cm-menu-item` 后读取 `data-action`：

- `user-all` → `renderUserComments(guid)`（§5.11）。
- 其他 → `showToast('开发中')`（统一占位）。

Toast：单例 DOM `<div id="cmToast" class="cm-toast">`，`position:fixed; top:24px; left:50%; transform:translateX(-50%); padding:8px 16px; background:rgba(20,30,41,.92); color:#fff; border-radius:6px; font-size:13px; opacity:0; transition:opacity .2s; pointer-events:none; z-index:100000`。`showToast(text)` 替换 text、设 `opacity:1`、6s 后 `opacity:0`。

```js
  if(back) back.addEventListener('click', returnToAllComments);
  bindReplyToggles();
  bindInspirationNoteButtons();
}
```

- 排序 tab 保留（默认 / 最热 / 最新 / 长评），与全部评论视图一致；视图模式下 `setCommentSort` 会自然重渲染该视图。
- 标签栏在 `usersec` 下隐藏（`.cm-drawer.usersec .cm-tags-wrap{display:none}`）；toolbar 排序 tab 可见。
- `returnToAllComments` 增加清空 `currentUserGuid = null`、移除 `usersec` class，复用 parasec 状态机。
- 引用行文案固定为「用户昵称的所有评论」（Figma 设计原型占位），不展示真实 guid。

## 6. 性能判断

CSV 样例规模为 7,493 行，其中一级评论 4,465 条、二级回复 3,028 条。这个规模在浏览器端一次性载入和渲染索引没有压力。

页面实际 DOM 量也可控：

- 全部评论默认每个对象最多 3 条一级评论。
- 单段评论最大约数百条一级评论。
- 回复默认折叠，点击时才展开。

因此 MVP 不需要虚拟列表。若后续单章评论达到数万条，再考虑分页、懒加载或虚拟滚动。

## 7. 测试方案

在现有 `test/smoke-test.sh` 基础上补充断言：

1. 默认打开页面后评论侧边栏展开。
2. 标题气泡显示章评数。
3. 段落气泡数量来自真实评论数据，`0` 不显示，超过 `999` 显示 `999+`。
4. 点击段落气泡后，只展示该段落一级评论。
5. 全部评论按段落顺序聚合，章评排最后。
6. 每个聚合块最多展示 3 条一级评论，超过时显示“查看本段 n 条评论”。
7. 标签点击后真实筛选一级评论，并保持聚合顺序。
8. 二级回复默认收起，点击按钮展开。
9. hover 评论对象能滚动定位正文，但不改变当前筛选状态。
10. 右侧工具栏在侧边栏开关状态下仍贴 viewport 最右。

数据预处理脚本也需要输出并校验统计值，例如总行数、一级评论数、回复数、章评数、段评数、孤儿回复数。

## 8. 风险与处理

| 风险 | 处理 |
| --- | --- |
| CSV 字段名较长且含中文标点 | 在预处理脚本中集中声明字段映射，不在前端散落引用原始列名。 |
| `评论对象` 文本不稳定 | 定位和聚合只依赖 `段落ID`，文本只用于展示。 |
| 头像、昵称、用户标签缺失 | MVP 使用 `用户guid` 和哈希头像兜底；用户标签隐藏。 |
| `自定义排序` 全为 `-1` | 默认按点赞数降序，再按原始行号稳定兜底。 |
| 数据量继续增大 | 先保持折叠回复和聚合展示；超过数万条再引入分页或虚拟列表。 |
| 改动影响现有布局 | 保留 flex order 约束，继续用像素探针验证右侧工具栏贴边。 |

## 9. 推荐实施顺序

1. 写 CSV 预处理脚本，生成归一化评论数据和统计报告。
2. 将 `index.html` 中演示数据替换为真实数据块。
3. 改造气泡计数和标题气泡。
4. 改造全部评论视图为按段落聚合。
5. 改造单对象评论视图。
6. 接入标签真实筛选。
7. 补充 hover/点击评论对象定位。
8. 更新 smoke test 并跑通回归。

整体上，这条路线可以最大程度复用现有页面，同时把复杂度集中在“数据清洗”和“状态渲染”两处，后续切换到后端 API 也比较顺滑。
