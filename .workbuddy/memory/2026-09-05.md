## 经验教训

- **用户对"数据对齐"特别敏感**："评论内容对应错位" / "评论对象对应错位"是用户视觉上一眼能看出的问题，迭代时优先级最高
- **CSV 的"段落ID"列语义不是固定的**：OCR 旧数据是按数组下标（0-based SECTION_COUNTS 数组），CSV 是按章节原文编号（1-based 段落号）。两者偏移 1 位但都"看起来对"，容易混淆。验证方法：idx=17 段评论数应等于 OCR 旧 SECTION_COUNTS[17]=257，吻合=偏移正确
- **截图是设计意图最强证据**：截图 1（标签云样式）+ 截图 3（评论底部操作）+ 截图 2（评论卡片整体）= Figma 视觉规范。PRD 文字描述比 Figma 截图弱，截图里的细节（如"赞"字 + IP 地址占位）一定要还原
- **代码层面**：把重复的 meta 行模板提到 `commentMetaRow()` helper 里，避免后续两处不同步的修改

## 2026-09-05 后续 · 标签云恢复 codex 原版节奏

用户反馈："标签大小和内容把 codex 的版本改错了"。

根因：上一轮我把标签云改成 height 28px / padding 0 12px / 字号 12px / 整体 4 列均分。codex 原版是 height 22px / padding 0 6px / 字号 12px / 短标签 3 列节奏、长标签独占一行（不是均匀 4 列网格）。

修法（commit `7e9b52c`）：
- CSS：`.cm-tags` 用 `display: grid; grid-template-columns: repeat(3, 1fr)` 替换 `display: flex; flex-wrap: wrap`
- `.cm-tag` height 32px / padding 0 14px / font-size 13px / 圆角 16px
- JS：`renderCommentTags` 根据 `t.name.length >= 9` 给标签加 `.cm-tag-long` class
- `.cm-tag-long { grid-column: 1 / -1; white-space: normal; height: auto; min-height: 32px }` —— 跨整行的长标签（如 27 字的"明确提及其他书籍..."）可以 2 行换行展示完整文字而不被 ellipsis 截断

视觉效果（截图 12/13）：5 行节奏 —— 3 个 / 3 个 / 1 个跨整行 / 3 个 / 1 个跨整行。

smoke-test 60 → 63 项（新增 3 项 cm-tag-long 断言：明确提及跨整行 / 建议加精跨整行 / 短标签不跨）。

经验：**codex 的视觉版本是有节奏的，不是均匀网格**。下次给 codex 接力时，如果要改标签云，先 git diff 看原版的 grid-template-columns 和 long class 实现，不要重写成"统一的" flex-wrap。
