## 2026-09-05 后续 · 返回全部评论避免"跳一下"

用户确认位置对了，但回到全部评论时会先看到顶部再切到目标位置——视觉上"跳一下"。根因：`innerHTML` 替换后浏览器可能先绘制一帧 scrollTop=0，再绘制 scrollTop=saved。

- 修法：在 `returnToAllComments()` 中保留同步设置 `scrollTop`，追加一个 `requestAnimationFrame` 兜底，确保布局稳定后再同步一次。双帧保险避免浏览器渲染中间帧造成的闪烁。
- 冒烟测试仍 91/91 通过（同步值稳定为 200，rAF 不影响测试断言）。
- **用户再反馈：还是跳一下，"第一次原来的位置就可以，不要在动一下"** —— 根因是 rAF 的第二次设置：同步设置已让位置正确，浏览器在两帧之间可能把 scrollTop 归零，rAF 再设回 saved 造成 0→saved 的二次视觉移动。
- 最终修法：去掉 rAF 和 visibility 过渡，只保留单次同步设置 `list0.scrollTop = savedAllCommentsScrollTop`。一次到位，无任何后续动作。91/91 通过。
- 经验：**滚动位置恢复用单次同步设置即可；rAF/双帧兜底在值相同时也可能触发浏览器重算 scroll，造成用户可见的"再动一下"。**

**调试链**（教训深刻）：
1. 疑似 padding transition 时序问题 → 删除 transition 无效
2. 疑似 offsetTop flush 时序 → 改增量 rect 校正，仍差 2px

## 2026-09-06 下午三 · 标签 hover 覆盖式菜单抖动修复

## 2026-09-06 下午四 · 标签 hover 抖动根治（wrapper 占位方案）

relatedTarget 修复不彻底——用户反馈仍抖动。真正根因：**cm-tags hover 时变 absolute 脱离文档流**：
1. cm-tags absolute 后脱离 flex 流 → 下方 cm-input/cm-list **上移**（布局剧变）
2. 且 absolute 的包含块是最近的 positioned 祖先（不是自身）→ 位置可能漂移
3. 元素位置改变 → 鼠标相对位置改变 → `:hover` 失效 → 又变回 relative → 元素回位 → `:hover` 又生效 → **循环抖动**

根治（wrapper 占位）：
- HTML：`<div class="cm-tags-wrap"><div class="cm-tags" id="cmTags">…</div></div>`
- CSS：`.cm-tags-wrap{position:relative;flex:0 0 auto;min-height:34px}`（**min-height 防 absolute 后塌陷**——没有它 wrapper 高度变 0，列表上移 34px，实测验证过）
- `.cm-tags.collapsed:hover/.hover-open`：`position:absolute + top:0（相对 wrap 保持原位置）+ left/right:0 + max-height:240 + overflow-y:auto + box-shadow`
- 效果：wrapper 始终占位 34px → 列表高度不变；cm-tags absolute 后 rect 从 wrap 顶延伸到菜单底 → **鼠标在菜单内仍在 cm-tags rect 内** → `:hover` 稳定保持 → 不抖

实测几何：wrapH 34→34、listTop 不变、tagsH 194、tagsTop 对齐 wrapTop、rect 覆盖菜单 ✓。194/194 通过。

**经验**：hover 展开类交互防抖动的铁律——**hover 触发的样式变化不能改变元素自身在布局流中的位置**（否则 :hover 判定基准变化导致循环）。用 wrapper 占位 + 内容 absolute 覆盖是标准解法。
