## 2026-09-05 后续 · 返回全部评论避免"跳一下"

用户确认位置对了，但回到全部评论时会先看到顶部再切到目标位置——视觉上"跳一下"。根因：`innerHTML` 替换后浏览器可能先绘制一帧 scrollTop=0，再绘制 scrollTop=saved。

- 修法：在 `returnToAllComments()` 中保留同步设置 `scrollTop`，追加一个 `requestAnimationFrame` 兜底，确保布局稳定后再同步一次。双帧保险避免浏览器渲染中间帧造成的闪烁。
- 冒烟测试仍 91/91 通过（同步值稳定为 200，rAF 不影响测试断言）。
- **用户再反馈：还是跳一下，"第一次原来的位置就可以，不要在动一下"** —— 根因是 rAF 的第二次设置：同步设置已让位置正确，浏览器在两帧之间可能把 scrollTop 归零，rAF 再设回 saved 造成 0→saved 的二次视觉移动。
- 最终修法：去掉 rAF 和 visibility 过渡，只保留单次同步设置 `list0.scrollTop = savedAllCommentsScrollTop`。一次到位，无任何后续动作。91/91 通过。
- 经验：**滚动位置恢复用单次同步设置即可；rAF/双帧兜底在值相同时也可能触发浏览器重算 scroll，造成用户可见的"再动一下"。**

## 2026-09-05 后续 · 折叠露半行根因追查（scrollHeight 上限）+ gap 回 6px

用户反馈：标签折叠 1 行时上方露出半行；gap 12 改回 6。

**调试链**（教训深刻）：
1. 疑似 padding transition 时序问题 → 删除 transition 无效
2. 疑似 offsetTop flush 时序 → 改增量 rect 校正，仍差 2px
3. 疑似 rAF 节流 → 改回同步 + setTimeout 兜底，仍差 2px
4. **中途发现僵尸服务器**：多个 python http.server 残留，8211 端口被返回旧文件的进程占用，导致页面代码与磁盘不一致，干扰了整段调试（教训：**改代码不生效先 `lsof -ti :PORT` 查端口占用**）
5. 最终手动验证增量校正数学时发现：**scrollTop 赋值无效**——`delta=2` 执行后 scrollTop 原地不动，因为 **scrollTop 已达 max（scrollHeight - clientHeight = 188-34 = 154）**
6. **真正根因**：选中标签在最后一行时贴顶需滚过 bottom padding，scrollHeight 上限不够，永远差 2px

**修法**：
- `.cm-tags.collapsed::after{content:'';display:block;width:100%;height:12px;}`——尾部 spacer 扩展 scrollHeight，max scrollTop 增加 12px，最后一行可滚到贴顶
- `syncSelectedTagInView` 用增量 rect 校正（`delta = rectDiff - padTop; scrollTop += delta`）+ setTimeout(220) 兜底重校正（幂等）
- gap 从 `6px 12px` 改回 `6px`

测试断言「折叠行对齐无半行」：`Math.abs(onRect.top - (tagsRect.top + padTop)) <= 1`。最终 126/126 通过。
